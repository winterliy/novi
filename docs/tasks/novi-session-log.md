# Novi 작업 재개 기록

## 2026-11-05

### 오늘 반영하고 푸시한 내용

- 예외 구문에 `finally`를 추가하고 compiler/VM 예외 처리 경로에 연결했다.
- 문자열 인덱싱, `.length()`, `foreach`를 UTF-8 코드포인트 기준으로 처리한다.
- 불변 tuple의 생성자 `tuple(...)`, 타입 검사, 인덱싱, 길이, 순회, 비교를 추가했다.
- list API에 `contains`, `remove`, `clear`, `insert`, `extend`, `pop()` 및 `pop(index)`를 추가했다.
- set에 `remove`, `clear`; dictionary에 `contains`, `remove`, `clear`, `length`; queue에 `peek`, `clear`를 추가했다.
- 예제와 언어 기능 문서를 갱신했다.

현재 `main`의 마지막 푸시 커밋은 `eac09c5` (`Allow indexed list pop in Novi`)다. 그 직전 관련 작업 커밋은 `c007159`, `db3413c`, `be2193f`, `a3a7348`, `482dc78`, `2bee41a`, `d273a99`, `8377734`, `5aa3e1c`, `db0e4c5`, `41c6551`이다.

### 검증 상태

- `git diff --check`는 각 변경 단위에서 실행했다.
- 빌드와 런타임 테스트는 실행하지 않았다. 따라서 위 기능은 아직 실행 검증 완료 상태가 아니다.
- 정적 코드 검토에서 `src/novi/runtime.cpp`의 tuple 비교 코드에 잘못된 포인터 역참조가 있어 컴파일을 막을 가능성을 확인했다.
- `src/novi/compiler.cpp`에서 `break`/`continue`가 현재 활성화된 모든 `finally`를 실행하도록 되어 있다. try 블록 안쪽 루프만 빠져나가는 경우에도 `finally`를 일찍 실행할 수 있으므로 제어 흐름을 수정해야 한다.

### 다음 작업 시작 지점

1. `src/novi/runtime.cpp`의 tuple equality 포인터 비교와 멤버 접근을 수정한다.
2. `finally` 실행 범위를 제어 흐름 기준으로 고쳐, try를 실제로 벗어날 때만 실행되게 한다.
3. Novi를 빌드해 현재 변경의 컴파일 오류를 복구한다.
4. lexer/parser/compiler/VM 기능에 회귀 테스트 체계를 추가하고, 앞서 추가한 예외·문자열·컬렉션 동작을 검증한다.
5. 이후 P0의 의미 분석과 함수/타입 정합성 작업을 이어간다.

다음 세션은 기능 추가보다 1~4번의 안정화부터 시작한다.

## 2026-11-08 재개

### 완료

- tuple equality의 잘못된 역참조를 고치고 parser의 try span과 `console.print` callback 컴파일 오류를 수정했다.
- `break`/`continue`는 현재 루프가 실제로 빠져나가는 try 범위의 finalizer만 실행하도록 컴파일 경로를 고쳤다. 정리 코드를 실행하기 전에 나가는 exception handler를 pop해 finalizer 오류가 바깥 handler로 전달되게 했다.
- catch 환경을 handler 종료 시 원래 환경으로 복원해 catch 변수 범위가 밖으로 새지 않게 했다.
- CTest 등록과 tuple equality, finally의 break/continue/return/throw, catch scope를 덮는 8개 회귀 사례를 추가했다.
- README 상태를 `개발 재개 (2026-11-08)`로 바꾸고 직접 빌드 명령에 `project.cpp`를 포함했다.

### 검증 결과와 환경

- 기본 `clang++` 명령은 CLT의 기본 include 경로에 C++ 표준 헤더가 없어 실패했다. SDK의 libc++ 경로를 `-isystem "$(xcrun --show-sdk-path)/usr/include/c++/v1"`로 지정해 C++17 빌드를 수행했다.
- 위 직접 빌드는 warning 없이 성공했고, 새 회귀 사례 8개와 `examples/*.nvi` 실행이 성공했다.
- 로컬에는 `cmake`/`ctest` 실행 파일이 없어 CMake configure와 CTest suite 자체는 실행하지 못했다. CTest 등록은 저장소에 추가했다.
- Rust와 asm은 이 안정화 변경에 사용하지 않았다. 병목 측정이 없는 상태에서 도입해도 최적화 효과를 입증할 수 없어서다.

### 다음 작업

1. CMake가 설치된 CI나 개발 환경에서 configure/build/CTest를 실행해 CTest 등록까지 확인한다.
2. resolver 다음 단계로 초기화 전 읽기, 타입 재대입·상수 binding 진단을 추가하고 shadowing 규칙을 확정한다.
3. 작은 VM benchmark를 추가한 뒤 실제 병목만 대상으로 C++ 최적화를 검토한다. Rust/asm은 C++ baseline보다 유의미한 이득이 측정되는 경로에만 고려한다.

### 2026-11-08 후속 구현 — 미정의 이름 검사

- 새 `Resolver`가 lexical scope를 따라 변수·함수·매개변수·반복 변수·catch 변수의 이름을 확인한다.
- 미정의 읽기/대입/constant 전환/상위 클래스 참조를 컴파일 전에 의미 진단으로 보고하고 바이트코드 실행을 막는다.
- 사용자 모듈 `export`는 아직 로더·모듈 scope가 없어 이름 검증을 보류하고, 실제 export 검증은 모듈 해석 단계로 남긴다.
- 현재 REPL은 이전 입력에서 선언한 이름을 유지하기 위해 정적 resolver를 건너뛰며, 실행 시 VM 검사를 사용한다.
- `undefined_name`과 catch 변수 범위 밖 참조 회귀 사례는 컴파일 전 오류로 거부되고 선행 출력이 발생하지 않음을 확인한다. catch 내부에서 변수 사용과 catch 종료 뒤 환경 복원을 실행 사례로 확인한다.
- 현재 CMake/CTest 미설치 제약은 그대로다. CTest 등록 실행은 다음 환경에서 확인할 것.

다음 단계는 CMake/CTest를 CI에서 실행하고, 초기화 전 읽기 및 타입 재대입·상수 binding 검사로 의미 분석을 확장하는 것이다. Shadowing 정책은 언어 프런트 task에 미결로 남아 있어 구현 전에 확정한다.

### 후속 구현 — 상수와 타입 진단의 기초

- `let` 상수에 대한 재대입과 고정 타입에 명백히 맞지 않는 리터럴 초기화·재대입을 실행 전에 진단한다.
- 숫자 세부 타입, 동적 표현식과 `constant` 실행에 따른 상태 변화는 기존 VM 검사에 맡긴다. 제어 흐름을 반영하는 정적 분석은 후속 작업이다.
- 직접 C++ 빌드, 기존 회귀 사례 및 새 오류 사례와 예제를 확인했다. CMake/CTest는 이 환경에 설치되어 있지 않다.

### 후속 구현 — VM 측정과 네이티브 경계

- 10만 회 range 합산 VM benchmark를 추가했다. 컴파일은 측정 전에 수행하며 결과를 검증한다.
- 문자열 길이의 ASCII 접두 구간을 C ABI로 분리하고 C++, Rust, macOS arm64 ASM 구현을 빌드 옵션으로 제공한다. 세 구성 모두 CTest를 통과했다.
- ASCII 전용 benchmark의 다섯 회 중앙값은 C++ 0.026769초, Rust 0.026758초, ASM 0.027442초였다. 이 기기·워크로드에서 C++를 기본값으로 유지하며, 이 수치를 VM 전체 성능으로 일반화하지 않는다.
- 함수·람다 바깥의 `return`/`output`을 구문 오류로 거부하고 함수 내부 반환은 유지했다. 관련 사례와 CTest가 통과했다.
- `vari 이름 : = 타입(값);`과 `let 이름 : = 타입(값);`에서 `=`를 잘못 중복 소비하던 파서를 수정했다. 전자는 서로 다른 타입으로 재대입 가능하고 후자는 상수로 유지됨을 확인했다.
- 함수와 람다의 중복 매개변수를 구문 단계에서 진단해 호출 시 인자가 조용히 덮어쓰이지 않게 했다.
- 변수에 대입하는 한 줄 람다가 선언의 세미콜론을 공유하도록 수정했다. 람다의 외부 변수 캡처와 재귀 함수 실행 사례를 추가했다.
- `catch` 내부에서 `continue`/`break`할 때 임시 catch 환경을 포함해 스코프를 정확히 정리하도록 compiler와 VM을 수정했다. `finally` 실행을 포함한 회귀 사례와 CTest가 통과했다.
- 반환된 람다가 종료된 함수의 캡처 변수를 유지하는 동작과 함수 인자 수 불일치 진단을 회귀 사례로 확인했다.
- 혼합 한글·ASCII 문자열의 길이 계산에서 네이티브 접두 검색을 한 번만 호출하도록 바꾸고 재현 가능한 benchmark를 추가했다. 전후 중앙값 0.11545초와 0.11215초의 표본이 겹치므로 유의한 속도 향상으로 단정하지 않는다.
- 추가 교차 측정(각 10회)에서 한 번만 접두 검색하는 버전이 중앙값 0.11618초, 기존 버전이 0.10721초로 확인되어 변경을 되돌렸다. 혼합 문자열 benchmark는 계산된 길이 1,000을 검증하도록 보강했다.
- VM 실행 시 불변 명령과 이름 상수의 불필요한 복사를 줄였다. 10만 회 VM 반복 benchmark를 15회 교차 측정한 중앙값은 0.03335초에서 0.02935초로 변했고 CTest가 통과했다. 표본 범위는 겹친다.
- `+=`, `-=`를 변수 대입에 추가했다. 기존 덧셈/뺄셈과 상수·고정 타입 검사를 사용한다. 인덱스 대입은 아직 별도 구현이 필요하다.
- 리스트와 딕셔너리 인덱스의 `+=`, `-=`를 추가했다. 대상 객체와 인덱스 표현식은 각각 한 번만 평가하며 관련 회귀와 CTest가 통과했다.
- 인스턴스의 `this.필드 = 값`과 `객체.필드 = 값`을 파서의 기존 VM 속성 대입에 연결했다. 생성자와 외부 속성 대입 사례를 확인했다. 선언된 class 필드 초기화와 private/static 접근 제어는 아직 미완성이다.
- 인스턴스 속성의 `+=`, `-=`를 추가했으며 객체 표현식이 한 번만 평가되는 사례를 확인했다. class 선언 필드의 초기화와 접근 제어는 아직 후속 작업이다.
- 클래스의 공개 가변 필드 선언을 보존하고 각 인스턴스를 생성할 때 초기화하도록 구현했다. 필드의 고정 타입은 초기화와 재대입 시 검사한다. `private`/`static`/상수 필드는 아직 구현되지 않아 파일과 REPL에서 명시적으로 거부한다. 메서드 접근 제어 등도 후속 작업이다.
- 공개 `let` 필드를 인스턴스별 초기화하고 재대입을 거부하도록 추가했다. 중복 필드 선언도 구문 오류로 거부하며, 비공개·static 필드는 아직 미지원이다.
- `private`과 `#`로 선언한 필드 및 메서드에 클래스 단위 접근 제어를 적용했다. 클래스 내부 메서드와 그 안에서 만든 클로저는 접근할 수 있고 외부의 읽기·쓰기·메서드 접근은 거부한다. `static` 구성원과 비공개 생성자는 아직 명시적으로 미지원이다.
